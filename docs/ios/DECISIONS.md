Профиль владеет счетами, операциями, целями, вишлистом, платежами, доходом (ставка, налог, часы), днём зарплаты и наценкой к ЦБ. «Можно сегодня» считается по данным профиля: у участников профиля оно одно и то же. Профиль — единица шаринга. Остаётся доменный `Settings` как составное значение: настройки профиля + настройки устройства | владелец |
| D22 | Переводы только внутри профиля. Деньги между профилями — отдельный расход в одном и доход в другом (версия 1) | владелец |
| D23 | Активный профиль выбирается меню в заголовке экрана; запись руками, голос, уведомления и аналитика работают в активном профиле. Голосовой промпт перечисляет счета активного профиля | предложено |
| D24 | Команда Apple `98SBSKJT3M` (Individual, платная Program, подписка активна). Продавец в App Store — имя владельца; организацию не оформляем | владелец |
| D25 | В голосовом промпте счета нумеруются позицией в списке (1, 2, 3…), а не id: UUID длинные и шумные для модели. Список в промпте и в `VoiceMapper` один и тот же, в одном порядке. Отличие от Android, где шёл числовой id | предложено |
| D26 | Проводки привязаны к профилю составными внешними ключами: база сама отказывается принять проводку на счёт или операцию другого профиля. Так данные общих профилей не смешаются даже при ошибке в коде | предложено |
| D27 | Порядок строк как на Android: операции с одинаковым временем — сначала записанная позже (`sequence` внутри профиля, его возвращает «Отменить»); цели — главная первой, затем по порядку создания (`createdAt` — счётчик, не время), чтобы «самая старая цель становится главной» пережило UUID-идентификаторы | предложено |
| D28 | «Стереть всё» удаляет и ключи API из Keychain (как `settings.clear()` на Android); `Repository` получает `SecretStore`, а бэкап его не получает и ключей не касается | предложено |
| D29 | Из Android-бэкапа не переносятся `lastAccountId` и `celebratedGoalId` (они личные для устройства); `reconciledAt` уезжает на счёт; Int-id становятся UUID в порядке возрастания, чтобы порядок по id сохранился | предложено |
