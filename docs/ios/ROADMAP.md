# Дорожная карта iOS-порта

Статусы: ☐ не начато · ◐ в работе · ☑ готово. Обновляй при закрытии каждой задачи.

Базовая версия Android: **0.15.0** (`fd2ea75`). Что выйдет в upstream позже, переносится отдельной задачей (см. «Синхронизация с upstream»).

Этапы идут по порядку. 🔑 — нужна подпись командой Apple (Team ID, App ID, iCloud-контейнер); аккаунт восстановлен, команда `98SBSKJT3M` (D24). Устройства: симулятор iPhone 17, iOS 26.2.

## Этап 0 — Каркас и ядро ☐

- `ios/project.yml` (XcodeGen): приложение `Golda`, bundle ID `com.f4studio.golda`, iOS 26.0, iPhone, Swift 6.
- Локальные пакеты `GoldaCore`, `GoldaData`, `GoldaSync`; наполняется только `GoldaCore`.
- `GoldaCore`: `Currencies`, `Fmt`, `Rates`, `Ledger`, `Budget`, `Base`, `Settings`, `Debts`, `Goals`, `Analytics`, `VoicePrompt`, `VoiceMapper`, `LocalDate`/`YearMonth`.
- Перенос 47 юнит-тестов из `app/src/test`. Тест `theMainCurrencyTravelsWithABackup` — про бэкап, он уходит на этап 1.
- CI: `.github/workflows/ios.yml` (сборка и тесты на симуляторе). Android-CI не трогаем.
- `.gitignore`: `*.xcodeproj`, `.build`, `DerivedData`.

Готово, когда:
- каждому из 47 тестов есть Swift-двойник, все зелёные, `swift test` идёт без симулятора;
- есть тесты на округление отрицательных .5 и на `Fmt` валют с 0 знаков (JPY, VND);
- `GoldaCore` импортирует только Foundation;
- пустое приложение собирается и запускается на симуляторе.

## Этап 1 — Данные ☐

- GRDB-схема с UUID и профилями: `profile` владеет счетами, операциями, проводками, целями, вишлистом и платежами; миграция v1 (см. `ARCHITECTURE.md` → «Данные»).
- Составной `Settings` активного профиля: профильная часть из `profile` + часть устройства из UserDefaults.
- Репозиторий с паритетом `Repo.kt`, всё в границах профиля: `save`, правка, удаление и восстановление операции, `reconcile`, `resetAll`, `ensureSeed`, `repairValuations`, обучение наценки; плюс создание, переименование и удаление профиля.
- Клиент ЦБ с запасным набором курсов; обёртка Keychain.
- Бэкап: импорт Android v1 (Int-id → UUID, `categoryId` → ключ, всё в профиль «Личный»), экспорт v2 со всеми профилями. Тест `theMainCurrencyTravelsWithABackup`.
- Демо-наполнение (`Demo.fill`, `Demo.samples`) по аргументу запуска в debug-сборке.

Готово, когда:
- сценарии `LedgerTest` проходят поверх настоящей БД (in-memory);
- бэкап, снятый с Android `Demo.samples`, импортируется, и балансы всех счетов совпадают до копейки;
- экспорт → импорт на iOS возвращает те же данные всех профилей;
- «Можно сегодня» двух профилей считается независимо; удаление профиля каскадно стирает только его данные;
- ключ API не попадает ни в БД, ни в бэкап.

## Этап 2 — Интерфейс по HIG ☐

Правила — в `DESIGN.md`. Порядок:
- **2a** Тема graphite + gold (light/dark), каркас `TabView`, переключатель профиля в заголовке, прототип микрофона и «+», Главная.
- **2b** Счета, страница счёта, сверка, форма счёта, долги (калькулятор досрочного погашения).
- **2c** Форма операции (расход, доход, перевод), «Сомневаюсь», цели, вишлист.
- **2d** Аналитика.
- **2e** Настройки, экран «Профили» (список, создание, переименование, удаление), онбординг (создаёт профиль «Личный»), String Catalog ru/en, иконка приложения, экран «О приложении».

Готово, когда:
- достижим каждый экран из списка в `DESIGN.md` → «Экраны»;
- светлая и тёмная темы выглядят одинаково выверенно; Dynamic Type до XXL без обрезки на ключевых экранах;
- у всех элементов есть метки VoiceOver;
- в String Catalog нет непереведённых ключей;
- сценарии XCUITest, парные `androidTest`, зелёные;
- скриншоты экранов сверены с `docs/screenshots/` и с HIG.

## Этап 3 — Голос ☐

- Запись WAV 16 кГц mono, лимит 60 с, отсечение касания короче 0,8 с и тишины.
- `VoiceProvider` + `GeminiProvider` (тот же запрос и схема, что на Android), офлайн-очередь, обработка при запуске, возврате в приложение и после ввода ключа.
- Экран согласия на отправку голоса стороннему ИИ до первой отправки (правило App Review 5.1.2(i)).
- Статус-плашка с «Отменить», состояния микрофона (слушаю, разбираю).

Готово, когда:
- фраза «шаурма 15 лари» на устройстве и в симуляторе с живым ключом превращается в трату с «Отменить»;
- заметка без сети или без ключа ждёт и разбирается позже, время операции — время записи;
- тесты провайдера идут на заглушке `URLProtocol` (успех, 4xx, 5xx, нет сети);
- до согласия на сеть не уходит ни один байт.

## Этап 5 — Синхронизация и шаринг по профилям 🔑 ☐

- **5a Спайк.** На двух устройствах с разными Apple ID: `CKSyncEngine` на private и shared БД, зона на профиль, `CKShare(recordZoneID:)`, приглашение, запись, удаление, выход. Вердикт — в `DECISIONS.md`.
- **5b** Синхронизация своих профилей (зона на профиль, private БД), исходящая очередь, слияние, `postingCount`.
- **5c** Шаринг: приглашение в профиль, участники, права, выход и прекращение доступа (O2, O3).
- **5d** Крайние случаи: офлайн-правки с обеих сторон, повторное создание удалённого, выход участника при открытом профиле, включение iCloud на готовых данных.

Готово, когда:
- на двух реальных устройствах с разными Apple ID трата, записанная на одном, появляется на втором при открытом приложении, и «Можно сегодня» у обоих одинаково;
- офлайн-правки с обеих сторон сходятся, балансы общих счетов равны;
- выход участника, прекращение доступа и удаление профиля владельцем ведут себя, как описано в `ARCHITECTURE.md`;
- без iCloud приложение работает локально, шаринг недоступен.

## Синхронизация с upstream

1. Один раз: `git remote add upstream https://github.com/shamil-aminov/golda.git`.
2. `git fetch upstream && git merge upstream/main` — конфликтов быть не должно, пока `app/` нетронут.
3. Смотри `git diff <база>..upstream/main -- SPEC.md app/src/main/java/sh/aminov/golda/domain app/src/test`. Каждое изменение — отдельная задача: тест, затем код в `GoldaCore`, затем UI.
4. Обнови «Базовую версию Android» в начале файла.
